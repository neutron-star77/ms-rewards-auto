# ADR-0001：调度唯一事实源 = `nas_cron.sh`

- 状态：已接受（记录既有事实；COMDATE 前由线上 `nas_cron.sh` 执行）
- 日期：2026-09-16（补录，仓库此前无 `docs/adr/`）
- 关联：CONTEXT.md §3 / §4、历史审计报告（"记录调度唯一事实源与立即模式限流"）

## 背景
本项目由 NAS cron 定时触发，历史教训反复出现：**"怎么触发"如果被改到多个入口（手动 ssh 起容器、面板脚本、cron 各行），行为就会漂移**，且无法审计。需要把"触发方式"收敛到**唯一**一处并让所有人都照它改。

## 决策
**凡是"什么时候/在什么条件下运行微软积分脚本"的触发逻辑，只改 `nas_cron.sh` 一个文件。** 当前语义（记录现状，改动仍走本 ADR 修订流程）：
- **随机两次/天**：cron 每 15 分钟调 `nas_cron.sh`；脚本首次运行时随机生成两个 HH:MM（去重，09:00–21:00 白天时段），仅当前时间命中方拉起容器 → 规避固定时刻被风控。
- **立即模式**：`nas_cron.sh --now|-n`（跳过随机时刻直接跑，延迟 ≤ `REWARDS_IMMEDIATE_DELAY_MAX_SECONDS`=60s）；`--force` 额外绕过手动冷却。
- **手动冷却**：手动任务完成后 20 小时内拒绝重复 `--now`（`MANUAL_COOLDOWN_SECONDS=72000`），凭 `--force` 绕过；正常 cron 不受此限。
- **暂停开关**：`disabled.flag` 存在时仅暂停定时触发，`--now/--force` 仍可运行；`manual_run.state` 记录手动运行态。
- **持久化**：`<scriptdir>:/app` 挂载，profile/`storage_state.json`/日志/状态文件都在 `/app/data` 下持久化。
- **调度随机性留档**：实际触发时刻 = 随机 HH:MM 之后最近一次 cron（≤15 分钟误差）。

## 后果
- 正面：触发逻辑单点可查、历史事故（入口漂移）不再复现。
- 代价：新增任何触发语义（如"每周三额外一次"）都必须先改 `nas_cron.sh` 并在本 ADR 追加修订，而不是手写 cron 行。
- 构成制度：**改动 `nas_cron.sh` 前，须同步更新本 ADR（用新增"修订"小节），否则视为越权。**
