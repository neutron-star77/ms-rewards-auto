# ADR-0002：earn/月任务 判"完成"只信绿勾徽章，配合涨分自审

- 状态：已接受（2026-09-16 W2 审计重构后仍成立；本节补齐"废弃假空圈信号"修订）
- 日期：2026-09-16（补录早期事实 + 本次修订）
- 关联：CONTEXT.md §3、`rewards_earn.py::scan_punchcard_rows`、历史审计报告"涨分自审/月度看门狗"

## 背景
earn/月任务的 DOM 由微软前端频繁改版。过去代码靠"字符串启发式 + 分号假设 class"判任务是否完成，结果：**判完成的信号时而取到真实、时而取到页面根本不存在的 class**，导致"已完成被漏判→重复点击"或"未完成被判成完成→漏做"，且都**静默**，靠日志/人工复盘才暴露。

## 决策
1. **完成信号只认真实存在的正向 DOM**：完成的唯一可靠信号 = 绿勾徽章类 **`bg-statusSuccessRewardsBg`**（dbg 快照实证存在）。
2. **废弃页面中不存在的负向假设**：早前用空圈类 `ctrlChoiceBaseStroke` 判定"当前周待完成"，快照实测该 class **计数为 0、根本不存在** → W2 起彻底弃用，改用"正向三态"判定：
   - `done`：行内含绿勾徽章（且不确定锁定）
   - `locked`：行内锁图标 或 文案 `4周后|⑤周后|到期日期|未解锁|即将开放|未开放|暂不可` —— 锁定周**绝不点击、不计完成/未完成**
   - 开放待点：既非 done 又非 locked（且能取到前往链接）
3. **周行扫描不再把 `<h3>` 当唯一锚点**：以「绿勾徽章 / 锁图标 / 搜索跳转链接」三类元素向上收敛到行容器，避免微软改版后整段静默漏扫；取不到前往链接的开放周**显式记入复检清单**而非静默跳过。
4. **涨分自审（点击后闭环）**：点击前往链接并拟真阅读后，reload 重扫确认该周绿勾翻转，以区分「没点到」与「点了不计分」（对应代码注释的月度看门狗）；为 `docs/adr/0003` 的周门控提供"翻转即 done"的判据。

## 后果
- 正面：判完成信号与实际 DOM 对齐，重复点击/漏做风险下降；锁定周不再被误点（把锁当"待完成"会误触发点击，最伤风控）。
- 代价：正向信号依赖前端 class `statusSuccessRewardsBg`，微软改了这个类名会再次失效 → 失效表现为"整周全部 done=false、OpenWeek 变多"，日志会明显异常，须第一时间人工核对；此风险由看门狗告警兜底。
- 判断 DOM 结构变化时，先落一份 `dbg_*.html`（`REWARDS_DEBUG=1`）再用实际 class/文案核对，不要靠记忆。

## 修订历史
- 2026-09-16（补录）早期：完成信号含 `ctrlChoiceBaseStrokeRest` 空圈假设 + 绿勾字符串启发式。
- 2026-09-16（W2 修订）废弃 `ctrlChoiceBaseStroke` 空圈假设；周行扫描改为正向三态 + 非 h3 锚点；无前往链接显式复核。
