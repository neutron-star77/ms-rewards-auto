# ADR-0003：earn 周任务「每周一次」门控 + 拟真化阅读 + 死代码收敛

- 状态：已接受（2026-09-16 W2 落地）
- 日期：2026-09-16
- 关联：ADR-0002 §4（绿勾翻转判据）、CONTEXT.md §4、`rewards_earn.py`

## 背景
earn 页"本月攻略"里有多个**每周一更**的周任务子项（开放周→搜索前往链接→计分→变绿勾）。旧实现的问题：
1. **无每周门控**：每轮跑都点未勾周，直到页面出现绿勾才停 → 当天已点过但微软计分延迟时会**同一周重复点击**，风控风险；
2. **"已完成"判断脆弱**（ADR-0002）；锁定周被误当待完成会被误点；
3. 打开前往链接后只是 `sleep(5~9s)`，不够拟真。

## 决策
在 `task_monthly_strategy` 里新增三层纪律（`rewards_earn.py::week_gate_ok/week_mark_clicked/week_mark_done/humanize_read`）：
1. **每周门控**（`weekly_click_state.json`）：
   - 键 `{week: ISO周, clicked: {子任务标题→ts}, done: {子任务标题→日期}}`；
   - 判定顺序：①在 `done` 中 → 整周期内不再碰；②在 `clicked` 中且未翻绿 → **跳过重复点击**（"每周一次"的核心）；③否则 → 允许点击并先写入 `clicked`；
   - 点击后拟真阅读并 reload 校验，绿勾翻转 → 移入 `done`；
   - 跨 ISO 周自动重置 → 下周重新开放再点。
2. **拟真化阅读**（`humanize_read`）：弹页随机向下滚动、停留、偶尔回滚，再静候（默认 8~18s）替代裸 sleep，降低风控。
3. **死代码收敛**：删除已确认无引用的遗留处理器 `task_activity_card`、`task_daily_links`、`open_link_handle_popup`（主流程已由 `task_dashboard_*`/`process_offers`/`task_monthly_strategy` 取代），降低"改一处残留在别处旧版"的维护噪音。调试落盘 `_snapshot` 改为仅 `REWARDS_DEBUG=1` 时生效。

补充规则（2026-09-24）：月度详情页中“完成第 N 天后等待”是开放任务的说明文案，不代表任务锁定。扫描时以启用的蓝色前往链接为最高优先级；每轮最多真人点击一个启用周任务，点击后刷新详情页确认绿色勾，避免同一月度卡片重复触发。

## 后果
- 正面：真正做到"每周点击一次"且翻绿后整周不再碰；重复点击/风控风险下降；锁周期内绝不误点；仓库缩小、改错地方的风险下降。
- 代价：新增一个状态文件 `weekly_click_state.json`（敏感度低，可入库，但暂不进 git 以保持一致）；门控若被误删，会退回"每轮都点"的旧行为——故门控函数名与文案刻意明显。
- 校验依赖 ADR-0002 的绿勾翻转为"完成"判据；若前端改版致绿勾不可见，门控会保守地继续"跳过已点击项"，表现为"某周一直点不着"的日志——按 ADR-0002 看门狗惯例人工核对。
